首页输入与下拉交互优化（2026-10-08）

本次实现
- 首页移除“先看方案 / 直接制作”，提交原始创作要求与素材说明。
- 首页复用 DSH 0.2.0-rc.2 的 InputBar、Lexical 编辑器和附件展示组件。
  上游没有独立可用的无会话 InputBar；因此固定复用仅供输入的本地会话，
  通过已固定版本的 slot/keyboard 适配转交 Frame 创建项目和上传素材。
  服务端禁止这个输入会话执行 Agent 模型步骤，附件选择阶段仅留在浏览器。
- 保留原生换行、撤销、输入法和附件操作；统一单层焦点边框、16px 输入字号。
- 首页加载中展示连接状态；导航切换不丢当前草稿、不被旧异步创建结果抢回。
- Frame 与原生剪辑工作台的 select 采用浏览器可定制菜单，圆角暗色面板、选中勾选。
  不叠加额外的开关事件；修复全局 Escape 导致菜单和设置弹窗同时关闭的问题。

实际验证
- 内置浏览器：点击下拉打开，再点关闭；Escape 先关闭选项，再退出弹窗。
- 首页：Shift+Enter 换行、撤销、添加及移除本地测试图片均正常。
- Enter 提交超长草稿触发 Frame 校验，按钮恢复可用；没有创建测试项目或调用模型。
- 实际 SlotCore 覆盖/恢复检查，以及隔离 DSH 会话并发与重启复用检查通过。
- JS 语法与 git diff --check 通过。本次没有跑全量生成测试、没有付费媒体调用。
- 截图：output/2026-10-08-home-composer/首页.png、下拉菜单.png。

兼容边界
- 可定制 select 在当前内置 Chromium 验证通过；不支持 appearance:base-select 的浏览器保留原生菜单。
- 首页输入适配绑定当前 DSH 版本；升级上游时需复核 composer slot 与 keyboard 接口。
