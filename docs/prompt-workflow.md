# 制作 Agent 的提示词与交接

主会话流程集中在 `harness/workflow-prompt.mjs`，由 bridge 注册到原生 `systemPrompt.section` 的 persona 插槽。两个运行 profile 共用这份文本；导演子会话使用独立 persona。新会话的主力模型遵循模型设置，已有会话保留原生选模。

流程按定位与简报、创意与方案、素材与声音、编排与预览、审片与交付组织。每个阶段说明产出及停点：只看方案则保存方案后停止，要求成片则继续至真实导出。创意方向已明确或用户授权自行决定时继续执行，有实质未决选择才提问。

`frame-commercial-video` 是短入口，生成、声音、审片、示例按需加载。原生剪辑参考、代码 recipe 与上游创作技能沿用。重写前后，主技能由 9,821 缩至 1,519 字符，直接工具描述由 13,709 缩至 8,824 字符；这些是文本规模，不代表模型费用或质量提升比例。

## 动态媒体能力

三种媒体服务的 `configuration().capabilities` 描述当前默认选择。明确改选服务、模型、质量或音频用途时调用 `get_media_capabilities`，参数为 `mediaType/provider/model/kind/quality`。

能力与提交共享本地校验声明，返回时长、画幅、分辨率、参考组合、声音模式及质量映射，标注 `limitsOrigin: local-validation`。它说明本项目已接入的范围，不证明远端模型权限或官方完整能力。无效旧配置不会阻断项目上下文；精确查询与真实提交仍校验输入。

## 创意导演

`creative_director` 的文字 prompt 第一行指定 `mode: proposal` 或 `mode: review`，旧调用默认 proposal。原生 `outputSchema` 与 `structured_output` 约束提交结果，纯正文不能替代交接。

- proposal 返回 `{kind, proposal, productionPlanInput}`，主会话核对后直接把 `productionPlanInput` 传给 `set_production_plan`。镜头与创意主张、声音设计、风险在普通计划和参考改编中都能保存。
- review 返回 `{kind, review}`，保留项与问题包含时间、证据类型、优先级和最小修复。评审不会自动覆盖制作方案。

导演只收到独立文字简报；提供的观察、转录和事实须说明来源及覆盖范围。默认简报上限为 30,000 UTF-8 字节，可用 `CREATIVE_BRIEF_MAX_BYTES` 调整；模型上下文和 32,768 tokens 输出上限保持独立。每用户轮六次委派预算沿用原生事件计数，第六次可执行，第七次拒绝。

旧商品模板保留编辑槽位，移除预填广告文案，使用已有中文正文字体。首页继续创建空白工程，不迁移或改写用户已有影片。

## 本次验收

本地隔离验证覆盖原生主会话、结构化导演、默认模型选择、媒体能力和普通/参考方案持久化，未调用付费媒体服务。浏览器中实际完成一次 8 秒纯代码方案与一次导演打磨：新版六镜头方案及创意字段已保存，停在方案，没有生成素材。

真实导演任务约 9 分 7 秒。首次远端响应约 8 分 32 秒，误加 `productionPlanInput` 被原生 schema 拒绝；约 35 秒后修正提交，包装交接约 12 毫秒。已明确导演只提交提案，接口自动包装，避免重复序列化。首个响应过慢尚无足够证据进一步归因；本次不宣称成片质量或平均速度提升。

同时修正“只有方案、没有素材”的忙碌状态：显示“正在完善方案”，不会误称正在准备镜头。
