下一批产品修复，按优先级
P0 · 导出已经完成，自动接续仍等待，导致结果不能顺利返回。
证据：23:45:40实际导出完成；23:46:22 await_tasks 指定代码界面版，之后出现「自动接续失败：任务不存在或不属于当前项目」。media-1持续running。根代理通过UI停止无效等待，再指示 get_export_status 查询已有ID，才恢复成片卡；没有重复渲染。
确证归因：server/agent.mjs:225 登记等待未保存videoId，:94恢复用conversation.taskVideoId=v-default；server/index.mjs:54、72的export任务适配器只列当前视频，查不到已完成的新影片导出。:109异常只清除awaiting，未给原生后台Job结算终态。
修法：统一任务查询的export适配器在项目范围列所有影片（getExports(projectId,true)），保留projectId隔离与UI当前影片过滤；等待登记保存目标影片，异常也通知Harness以failed结算。只做隔离验证，不用真实媒体生成复测。

P0 · 大任务迟迟不形成可见进展，长输出中断后重走当前步骤。
证据：三个风格场景轮约 8分55秒仍无提交/预览；全片续做轮约14分钟出现 Anthropic 流未正常结束，未完成工具参数不能落盘。之后靠外部助手拆为单场景，才逐段完成。
归因：执行粒度、提交恢复机制与传输故障；不是生图模型质量，也没有证据是输出上限或本次413。
修法：先做一镜形成风格帧；按场景写入、提交、预览；记录已完成阶段，失败从最近阶段恢复。不能执行不完整工具参数。

P1 · 当前方案和初始简报混在一起。
证据：get_project_context 原样提供旧 brief；set_production_plan 更新方案却不更新它。旧 brief 仍要求使用真实截图与概念生成图，和用户本轮决定冲突。
落点：server/agent.mjs:76、server/project.mjs:101、harness/plugin.mjs:184。
修法：保存明确的当前简报/方案覆盖关系，同时保留 initialBrief；上下文标清哪个是当前要求。不要从片段文字猜写或删除原始需求。

P1 · Agent 创建新影片后，工作台/影片导航没有跟着更新。
证据：新变体提交与预览正确，原影片完整；页面仍显示原版 iframe 与旧历史，新预览却已经出现。
落点：src/app.js:188、589、622、679；server/agent.mjs:152、267。
修法：创建变体发布目录更新事件；幂等刷新导航，明确当前影片；用户切换走同一 openProject 路径。不能靠刷新页面长期代替修复。

P1 · 提交后再编辑，文件读状态可能失效。
证据：本轮 commit/preview 后，未有外部代码修改，相同会话 edit 却多次遇到「file changed since it was read」；重读后恢复。
候选归因：提交同步重写文件与原生读取标记不一致，尚未核实内部根因。
修法：相同内容不重复重写，或明确返回需要重读的文件；保留并发修改保护。

P2 · 进度和失败提示仍在消耗用户注意力。
证据：字体探测尾部缺失 glob 的非零退出被标成红色失败；大量英文思考、技术路径和内部工具名仍展示；有无新编辑的重复提交。
修法：区分非阻塞探测、可恢复错误、真正阻塞；默认显示中文阶段和产物，详情折叠；比较整个工程文件集，避免空提交。
本次额外观察：导出等待显示「等待素材」，把渲染、模型处理和媒体生成混在一起；成片返回时原等待卡一度仍显示导出中。需要用同一任务状态刷新旧卡片，避免结果就绪和正在处理同时出现。

P2 · 视觉质量不能靠静帧编译成功判定。
本轮仍出现重复的「创意＋色条＋圆点」、比例不平衡、字幕边距与波形越界等，需要导演约束、字体角色、媒体语义和构图检查。最终应检查完整导出与镜头衔接，不能把工具成功直接称为精品。
