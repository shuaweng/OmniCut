# Gemini 成片审片

模型设置 → 视频理解，可分别选择「参考视频服务」与「成片审片服务」。成片审片可以使用 Gemini，而脚本、分镜和参考拆解继续使用原来的创意模型。Agent 的 `analyze_video` 和工作台「审片」入口使用同一服务。

当前已验证的 ZenMux 连接：

- 接口地址：`https://zenmux.ai/api/vertex-ai`
- 模型：`google/gemini-3.8-flash`
- 接口方式：流式 `streamGenerateContent`（设置值 `stream`）
- 鉴权：服务端 `Authorization: Bearer` 请求头，密钥只存本机 `.env`
- 审片思考强度：`MEDIUM`

这条连接使用 Vertex AI 原生多模态协议。[ZenMux 官方说明](https://zenmux.ai/docs/api/vertexai/generate-content.html)确认了流式路径、Bearer 鉴权与思考强度字段；视频、音轨和截帧按 [Google 的 Content / Part 格式](https://cloud.google.com/vertex-ai/generative-ai/docs/reference/rest/v1/Content)提交，视频采样信息使用 `videoMetadata`。工作台根据接口地址适配协议，用户填写上述地址、模型与流式方式即可。

Right Code 历史验证的连接仍保留：

- 接口地址：`https://www.right.codes/gemini`
- 模型：`gemini-3.8-flash`
- 接口方式：流式 `streamGenerateContent`
- 鉴权：服务端 `x-goog-api-key` 请求头，密钥只存本机 `.env`

渠道的 [原生 Gemini 调用文档](https://docs.right.codes/docs/rc_extension/curl) 描述了流式协议；实际测试确认用户提供的 `www.right.codes/gemini` 地址可以响应，未自动跳转到文档里的其他域名。

审片发送三种同源证据：完整转码视频、从同一文件提取的完整音轨，以及 8 张带原片时间的清晰截帧。视频用于连续动作，音轨用于真实台词和声音，截帧补充小字、包装和遮挡细节。截帧与商品对照图分别标明，不能把商品资料写成原片观察。

视频最长边限制为 1280，保留比例且不放大小尺寸素材；独立音轨保留立体声和视频起点之前的静音，使延迟开始的音轨仍对齐原时间线。请求的内部视频采样为 4 fps，不能把模型报告当成逐帧验收。快速动作、精确字幕时序和混音响度应对照实际片段、语音对齐或技术检测复核。当前短广告以内联数据提交，视频、音轨和截帧合计超过 14 MB 会明确报错，不截短或省略音轨。

窗口持续展示任务阶段，结果绑定被检查的具体成片版本。点击问题跳转到对应时间，也可引用到当前对话。声音观察和不确定项默认折叠；网络或模型失败不会偷偷用关键帧分析冒充完成原生声音检查，也不会自动重发付费请求。

## Right Code 历史实测

2026-10-10，经用户授权，将已有的两版 15 秒可口可乐广告发送到指定 Gemini 渠道，将首版截帧发送到指定 Opus 渠道。没有生成新媒体。原始结果、视频和复核截帧保存在本机 `output/gemini-review-comparison/`，不进入 Git。

**Gemini 的原生听音有价值，但不能据此宣布审片全面优于 Opus。** 当时的混合配置在首版找到了包装重复容量文字和片尾标题遮挡两个真实问题，在最终版没有再报已修正的标题遮挡；仍有时间误差和未经证实的画面判断。参考拆解保留 Opus，成片审片单独使用 Gemini，业务入口与 Agent 工具共用同一服务。

表中混合配置的 40／56 秒是包含媒体准备的总时长，对应模型分析耗时分别为 34.6／52.6 秒。渠道速度对照使用下文的模型分析耗时，避免把两种口径混在一起。

Opus 流程本次未得到可用的语音转录：本地 WhisperX 启动受到 NLTK 资源下载路径检查阻止，未绕过限制。因此这是产品管线对照，不是两模型在完全相同输入下的纯模型评测，更不能由一次格式失败断言 Opus 审片更弱。

新混合首版请求总用量 14,309 tokens，其中输入 12,062（截帧约 9,407）；旧首版请求总用量 7,765、输入 2,325。虽然本次更快，新增截帧增加了输入，不能称为普遍更快或更便宜。渠道实际账单未单独核算，不从 token 数估算人民币费用。

最终版混合请求总用量 15,325 tokens。其新增两项问题不是已确认缺陷：9.3 秒罐底有接触阴影，9.8 秒是手握罐正常抬起；10.679／12.814 秒字标受到手部和曲面透视影响，14.95 秒原片放大后仍可辨，不能支持“乱码、字母缺失严重”的 high 判断。报告保留原始模型输出，不改写成虚假的全通过。审片默认不自动修改或重生成视频。

## ZenMux 对照实测

2026-10-10，在用户授权下，将同样的两版可口可乐成片，以及大宝旧成片提交到 ZenMux 的 Vertex AI 连接。可口可乐沿用完整视频、同源音轨、8 张带时间观察帧和 medium 审片配置。原始报告保存在本机 `output/zenmux-review-comparison/`，不进入 Git。

这次对照支持“两个样本分析更快，部分问题描述更准”，不能证明模型智力普遍更强，也不能以问题条目减少宣布整体审片更好。音色、配乐风格和混音描述仍未做本轮独立听音复核。

Right Code 的两条混合请求输入均为 12,062 tokens，ZenMux 均为 14,457，视频、音频与图片的分项统计也不同。协议字段、媒体处理和渠道计量方式都可能影响这些数字；输入用量差异不能证明渠道换了模型，也不能据此认定更便宜。实际费用以渠道账单为准。

Opus 比这几轮 Gemini 更愿意保留遮挡、手指数量、左右手关系和连续动作的不确定性，这有助于避免“全部正常”的过度保证。但它仍未可靠识别这条成片的已知问题，不能作为自动验收过关的依据，也不能据此宣布能自动替代 Gemini。第三轮由人工选择和放大画面，应与自动审片分开记录，不能算作系统自动定位或自动检出。

Opus 使用大量静帧，Gemini 使用视频、独立音轨与少量观察帧，两者输入和管线不同。本次只能比较各自流程对这条成片的实际帮助，不能当作完全相同输入下的纯模型评测，也不是公平费用对比；未核算渠道账单，不编造人民币费用。

## 声音与时间证据

- 4 秒合成片的实际音轨有 4 次提示音。只提交带音轨 MP4 时，用量没有 AUDIO，模型误报全程无声。增加同源 MP3 后出现 AUDIO 用量，但仍把 4 次提示音误判为 1 次。AUDIO 用量只说明渠道处理了音频，不证明听音正确。
- 8 秒合成中文片，模型准确转录“欢迎来到创作空间。把你的想法交给我，一起做出精彩视频。”，并找到画面写“图片”、台词说“视频”的语义矛盾。短提示音和精确时序仍未全部识别。
- 可口可乐旁白原音轨在 12.1 秒起，模型多次给出约 11 秒起的时间。模型适合指出可疑片段，不能代替强制对齐生成字幕时间戳。
- 本轮未对 Gemini 所述音色、背景音乐风格或混音自然程度做独立听音复核，不将这些描述计作已证实提升。响度仍以音频技术检测为准。

## 一起修正的产品问题

- 审片窗口持续显示阶段与加载动效，任务完成后显示结果；不会提交后立刻关窗，让用户不知道去哪看。
- 报告绑定被检查的导出版本，避免首版报告被当成最终版问题。声音观察、不确定项和错误细节折叠展示，点击问题定位到时间线或引用到当前对话。
- 模型设置分别选择参考与审片，也支持审片沿用参考服务；不改创意和任务执行模型。密钥只由服务端读取，公开配置不返回密钥。
- 视频理解设置里的服务商入口跟随填写的自定义 HTTPS 地址；使用 Google 官方接口时仍进入 AI Studio，避免使用其他服务商却被引导到 Google 密钥页面。
- 收紧审片判据：主标题不必逐句复述旁白，未提供品牌 VI 时不能发明官方字体和落版规则，修复优先考虑局部处理或替换一个镜头。
- Opus 对完整 JSON 附前言的响应可保守恢复；截断、含多个候选或尾部说明的结果仍拒绝。原始响应在解析之前私有保存，避免格式错误后只能再次付费重试。

此前相关本地隔离检查 38 项通过，覆盖流式截断、失败分类、配置继承、音轨起点、转码比例、参考流程和 JSON 恢复。本次 Vertex AI 新协议相关 21 项隔离检查也已通过，覆盖连接格式与协议处理；两轮检查不合并计算为新的总数。真实付费测试与隔离检查分开执行，协议检查通过不代表模型能可靠发现所有画面缺陷。
