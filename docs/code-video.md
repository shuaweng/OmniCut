# 代码与镜头一起制作

OmniCut 的代码动效使用已有的原生 Author Package、Film、时间线和逐帧渲染器。代码镜头不是提前生成的一段不可编辑 MP4，也不另建一套剪辑工程。

## 本次接入

- 制作方案的每个场景可以选择 `generated`、`code` 或 `hybrid`。纯代码场景不触发图片、视频服务；混合场景生成底片后，由 Agent 在同一工程里编排。
- 主 Agent 可以选 Opus；创意导演子代理仍负责文案、分镜和评审，工程工具属于主 Agent。
- `preview_frames` 按工程的真实帧时钟渲染指定帧、切点两侧或采样间隔。图片通过原生附件进入模型上下文；聊天中可查看、定位和引用这些画面。小样不超过 3 秒，工程小样为无声画面预览。
- `probe_export` 读取实际成片的片长、画幅、帧率、音轨、响度和疑似黑帧、静帧区段。它是技术检查，不能替代试听和创意判断。
- `analyze_beats` 在本地分析音乐，并按素材版本缓存。BPM、拍点和强重音候选保持各自含义；不把低置信度起音假称稳定拍子，不猜测 intro/drop 或小节强拍。
- 拍点绑定原生音轨，跟随实际移动、裁切、播放速度和循环重新映射。时间线支持显示和吸附；版本或来源不一致时停止使用旧映射。
- 项目的有效原生组件可从动效库保存并跨项目复用。属性面板通过组件公开的真实参数修改文字、颜色和节奏，无需重写源码。
- 导出显示原生已渲染帧数，期限按帧数、画布和实际速度估算。渲染失败保留真实失败帧及该帧上的实体候选，供局部修复。

## 验证边界

已用隔离工程验证指定帧渲染、短样片、附件进入模型请求、实际音轨拍点移动和版本隔离；未将这些检查当作商业片质量证明。

方案预览按用户意图提供：要求“先看方案”时保留选项与预览；要求“直接制作”时不强制经过三方案选择。完整视频的听觉和运动理解仍需要支持该输入的模型，抽帧检查不冒称完整声画审片。

## 真实任务记录：小米 17 · 灵感不等人

在产品对话里用 Opus 主 Agent 完成了 20 秒、1920×1080、24fps 的混合工程：已有视频镜头与新写的银线字排、取景角标共用原生时间线，组件保存为“银线取景”。最终导出完成 480/480 帧，本地渲染约 29 秒；实际成片有一条立体声音轨，测得 -18.06 LUFS、-1.67 dBTP。这些数值只说明导出与技术探测成功。

实际抽帧发现过银线与文字重叠、角标延伸超过切点和位置偏移，Agent 修改后重新渲染检查。首次“角标缺角”的模型判断与当时的图片证据不一致，不能当作已证实的渲染缺陷。

小样第一次因选帧与片段的资源范围重叠而失败，修复为原生区间并集后，重新通过产品对话生成了 2.5 秒、1080p 的无声小样，播放器完整播放到结尾。旧的“隔离小样已通过”结论不能证明修复前的原生分支正常；修复后的隔离与真实项目结果才是有效证据。

工作台里实际修改了开场文案和主色，源工程写回，实时画面呈现橙色新文案；验证后恢复原文案与色彩，并通过顶栏重新导出 20 秒成片。修复了文本控件 Enter/离开输入框的保存与重复提交，也为编辑器脚本增加构建命名空间，避免重建后入口文件同名而继续使用旧缓存。运行中的真实检查帧沿原生过程插槽即时显示，完成按钮仍等待整轮结束。

Opus 在这个任务中仍有明显时延：第一次出现 300 秒无响应，另一轮过度构思被停止；采用 Low 的继续制作约 16 分钟，之后一次只请求预览的对话仍用了约 110 秒。其中本地预览工具为 9.49 秒，前后两个模型步骤共约 100.43 秒；步骤开始至首个可见内容分别约 36.01、56.67 秒。日志没有 HTTP 首包时间，不能进一步把它们认定为渠道排队或模型计算。制作写法与真实 thinking 已接入，不能因此宣称速度问题已经解决。

同一 revision `8:23b4716b627c8685` 已两次完整导出并比较 480 帧，123 帧的解码像素不完全相同，主要集中于字排与银线。进一步在冻结的原生 Composition 上重复捕获 5 张编码前 PNG：4 张逐像素一致，一张仅 0.086% 像素不同，平均误差 0.00595/255。已确认存在极小浏览器光栅差异，不能把全部差异归给 H.264 压缩，也没有布局跳动或时序错帧的证据。保留原生渲染器；计划要求的逐像素一致尚未达成。

本轮未完成计划里的六组模型基线对比、30 秒 60fps WebGL 验收，也未做完整成片的听觉、连续运动模型审片。

开发环境里还观察到原生文件改动统计会列出同一仓库中同时发生的产品代码变更，并非全部由视频 Agent 修改。现在会话代码副本建立独立 Git 范围，原生改动统计不会再向上发现整个产品仓库。隔离实测只记录本次修改的 `hypit/main.svml`，外层 README 与 Git index 保持原样；不迁移既有历史，不替代原生工程 revision 与项目撤销。

手动导出曾误把已完成对话重开为“正在导出成片”：原有素材展示归属同时包含用户和 Agent 提交的任务。现在仅 Agent 工具提交记录当前请求归属，聊天根据该记录、真实工具结果与等待任务判断是否完成；用户手动操作仍显示在项目进度与素材中。已通过顶栏实际复验：渲染期间项目显示进行中，对话保留完成标记，随后 480/480 帧导出成功。
